Endpoint
POST /api/listing/import
Content-Type: application/json
Auth: Bearer token (role: User, Landlord or Admin)

Purpose
Single RPC to create Address -> Property -> RentalUnit(s) -> Listing(s) and reconcile uploaded photos + listing amenities.

Request DTO (frontend responsibilities)
- Use the existing `ListingImportDto` shape.
- Top-level fields:
  - `Property` (PropertyDto) — include nested `Address` (AddressDto) when creating a new address.
  - `Units[]` (array of UnitImportDto)
  - `SafetyDetails` (optional, ignored server-side for now)

UnitImportDto fields (per unit)
- `RentalUnit` (RentalUnitDto): UnitNumber, Bedrooms, Bathrooms, Notes, CapturedBy, etc. Do NOT set PropertyID (server will set from created property).
- `UnitTypeName` (string): friendly name, e.g. "Apartment" (server resolves to UnitTypeID).
- `Listing` (ListingDto): Title, Description, BaseMonthlyRentAmount, Currency, MinimumLeaseMonths, MaximumLeaseMonths, Notes, IsFurnished, IsPetFriendly, CapturedBy, etc. Do NOT set ListingTypeID or RentalUnitID (server will set/resolve).
- `ListingTypeName` (string): friendly listing type name (server resolves/creates ListingType).
- `SelectedAmenities` (string[]): amenity names e.g. ["WiFi","Washer"], server resolves against AmenityCatalog.
- `ListingPhotos` (ListingPhotoDto[]): previously uploaded photos to reconcile. Common pattern: `CapturedBy` had values like "2_Unit_1_"; server finds photos with matching `CapturedBy` and null ListingID and updates them to the real ListingID.

Important server behaviors
- Address: If `Property.Address` is provided, server creates Address and returns AddressID. Property.AddressID will be set server-side prior to creating property.
- Property: created from `Property` object. Return PropertyID.
- UnitType & ListingType: when client does not have the catalog ID, provide the name in `UnitTypeName` / `ListingTypeName`. Server will search catalog and create item if missing.
- RentalUnit: server will create `RentalUnit` and return RentalUnitID.
- Listing: server will create Listing and return ListingID.
- ListingAmenity: server resolves amenity names and creates ListingAmenity records.
- ListingPhoto reconciliation: provide photos with `CapturedBy` values you used when uploading. Server will match and call updateListingPhoto to set ListingID.

Response (ListingImportResultDto)
- `AddressID`: GUID or null
- `PropertyID`: GUID
- `Units`: array of { UnitNumber, RentalUnitID, ListingID }

Notes / tips for frontend
- Set `CapturedBy` on uploads and DTOs so photo reconciliation can match records uploaded earlier (CapturedBy value is used).
- Do not pre-populate IDs (AddressID, PropertyID, RentalUnitID, ListingID) when creating new records. The server returns the created IDs.
- Use application/json and include a valid authorization bearer token with appropriate role.
